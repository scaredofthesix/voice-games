# Voice Games documentation

This directory holds the maintained documentation for Voice Games. The same content is
browsable as a hosted site at <https://scaredofthesix.github.io/voice-games/docs/>.

New here? Start with the [customer handover](./customer-handover.md) for the current
transition status, or the [root README](../README.md) to play the product.

## What each document contains

| Document | What it covers |
|---|---|
| [customer-handover.md](./customer-handover.md) | Current handover status, what is transferred vs. retained, configuration and secrets, and setup/recovery/verification steps. Start here for transition. |
| [roadmap.md](./roadmap.md) | What shipped each sprint and what remains for the current course version. |
| [user-stories.md](./user-stories.md) | The product backlog user stories with story points, MVP mapping, and status. |
| [definition-of-done.md](./definition-of-done.md) | The team's Definition of Done gates a change must pass before it is merged. |
| [development-process.md](./development-process.md) | Development process and configuration management: branching, reviews, releases, and deployment. |
| [quality-requirements.md](./quality-requirements.md) | The measurable quality goals (accuracy, performance, accessibility) based on ISO/IEC 25010. |
| [quality-requirement-tests.md](./quality-requirement-tests.md) | How each quality requirement is verified automatically. |
| [testing.md](./testing.md) | The automated test strategy and quality gates (unit, integration, coverage, CI). |
| [user-acceptance-tests.md](./user-acceptance-tests.md) | The UAT scenarios the product is expected to pass, and their latest execution results. |
| [architecture/README.md](./architecture/README.md) | Architecture overview with static, dynamic, and deployment views, plus the [decision records (ADRs)](./architecture/adr/README.md). |
